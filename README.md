# prompt-magic

Prompt generation web app: an ASP.NET Core (.NET 10) API plus a SvelteKit (Svelte 5, TypeScript) single-page app.

## Layout

| Path | What |
| --- | --- |
| `src/PromptMagic.Api` | Minimal API host, OpenAPI, health check, serves the built SPA from `wwwroot` |
| `src/PromptMagic.Core` | Prompt-generation logic, no web dependencies (`IPromptGenerator`, offline template generator) |
| `src/PromptMagic.Infrastructure` | OpenAI-compatible LLM client, options and DI registration |
| `tests/` | xUnit tests (`Core`, `Infrastructure`, `Api` with `WebApplicationFactory`) |
| `web/` | SvelteKit app (adapter-static, SPA mode), pnpm |

## Prerequisites

.NET SDK 10 (see `global.json`), Node 24+, pnpm.

## Develop

Run the two halves in separate terminals:

```bash
dotnet run --project src/PromptMagic.Api     # API on http://localhost:5080
cd web && pnpm install && pnpm dev           # UI on http://localhost:5173, /api proxied to the API
```

OpenAPI document (Development only): http://localhost:5080/openapi/v1.json

### Regenerate the typed API client

With the API running:

```bash
cd web && pnpm gen:api    # writes src/lib/api/schema.d.ts, commit the result
```

## Test and check

```bash
dotnet test PromptMagic.slnx
cd web && pnpm lint && pnpm check && pnpm test
```

## Docker

```bash
docker build -t prompt-magic .
docker run -p 8080:8080 prompt-magic
```

Builds the SPA, publishes the API, and serves both from one container on port 8080.

## CI/CD and contributing

Changes land on `main` through pull requests; see [CONTRIBUTING.md](CONTRIBUTING.md). GitHub Actions runs
CI on every PR (backend, frontend, API contract, Docker build, aggregated by **CI passed**) and publishes
`ghcr.io/ikkeflikkeri/prompt-magic` for every commit on `main` and every `vX.Y.Z` tag.

## LLM configuration

Prompts are generated by any OpenAI-compatible chat completions endpoint (`POST {BaseUrl}/chat/completions`): OpenAI, Ollama, OpenRouter, vLLM, LM Studio and so on. With no LLM configured the app falls back to a simple offline template generator, so it runs out of the box.

| Setting (`Llm:` section) | Env var | Default | Notes |
| --- | --- | --- | --- |
| `Model` | `Llm__Model` | empty | Model name for your endpoint. Setting this (or `ApiKey`) enables the LLM. |
| `ApiKey` | `Llm__ApiKey` | none | Sent as a Bearer token. Optional for local servers such as Ollama. |
| `BaseUrl` | `Llm__BaseUrl` | `https://api.openai.com/v1` | API root, without `/chat/completions`. |
| `SystemPrompt` | `Llm__SystemPrompt` | built-in prompt-engineer prompt | Instructions sent as the system message. |
| `TimeoutSeconds` | `Llm__TimeoutSeconds` | `60` | Per attempt (5-600). Failed calls are retried twice. |

Examples:

```bash
# OpenAI (or any hosted provider): keep the key out of git
cd src/PromptMagic.Api
dotnet user-secrets set "Llm:ApiKey" "<your key>"
dotnet user-secrets set "Llm:Model" "<model name>"

# Local Ollama, no key needed
dotnet user-secrets set "Llm:BaseUrl" "http://localhost:11434/v1"
dotnet user-secrets set "Llm:Model" "<a model you have pulled>"
```

Invalid settings (for example `ApiKey` without `Model`) stop the app at startup with a clear message. If the model call fails, `POST /api/prompts/generate` returns a `502` problem response with a safe message; upstream details are logged, never returned.

## Secrets

Never put LLM API keys in the frontend or in git. Locally use `dotnet user-secrets` in `src/PromptMagic.Api`; in production use environment variables or a secret store.
